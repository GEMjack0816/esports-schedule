## Recommended sequence

1. Merge CI isolation first so dependency changes receive repeatable PostgreSQL, unit, lint, build, and client-bundle checks.
2. Open a dedicated Next.js patch/minor upgrade PR for `next` and `eslint-config-next` at `16.3.1` or newer compatible releases; verify Server Actions, image optimization, caching, and browser flows.
3. In a separate lockfile-only maintenance PR, update compatible `brace-expansion`, `js-yaml`, and `nanoid` transitive patches without `--force`; keep only changes that pass the full CI matrix.
4. Track `drizzle-kit` upstream. Do not downgrade or force an incompatible nested esbuild override solely to reduce the audit count.

The reported severities should not be treated as proof that every advisory is reachable. Next.js and Sharp deserve prompt remediation because they intersect active server paths; the Drizzle/ESLint findings are restricted to trusted development and CI tooling in the current architecture.
